### 0.3 Better Auth + OAuth 單一白名單與登出零殘留
- [ ] 設定 Google / GitHub OAuth，**關閉 `cookieCache`**（強制每次走 DB Session 查詢，確保登出即時作廢）
- [ ] 實作 OAuth 白名單前置攔截：建立 User／Account／Session 前驗證 `email.trim().toLowerCase() === OWNER_EMAIL.trim().toLowerCase()` **且 `emailVerified === true`**
- [ ] 實作 `requireOwnerSession()` 統一驗證函式：檢查 HTTP-only Session 存在、未過期、且對應使用者 Email 仍吻合當前 `OWNER_EMAIL`
- [ ] 設定 `proxy.ts`（Node.js runtime）：僅負責未登入頁面導向 `/login`，不作為唯一資安邊界
- [ ] 實作完整登出端點與客戶端清理流程：
  - 呼叫 Better Auth `signOut()` 刪除 DB `Session`
  - Response 明確過期所有 auth cookies，並附帶 `Clear-Site-Data: "cookies", "storage", "cache"`
  - 所有受保護頁面／API 回傳 `Cache-Control: private, no-store, max-age=0`
- [ ] **Checkpoint 0 驗證**：未登入呼叫私人 API / Server Action 一律回 `401`；非白名單或未驗證 Email 的 OAuth 登入遭拒絕；完成後量測並將專案初始覆蓋率與 Main JS bundle size 寫入 `CONSTRAINTS.md` 棘輪基準表
